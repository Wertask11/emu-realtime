# Knowledge Lab 完成機能の実装と検証範囲

2026-10-14。基準 main は `ceab38ec7149b2d3f6cd815f0827e99e9c4e9fdf`。PR #195 の成果を引き継ぐ追加実装。旧 `architecture.md` は初回実装時の記録であり、追加機能には本書を適用する。コード実装、模擬APIテスト、実Gemini成功、Production公開を別々に判定する。

## 分類と移行

`taxonomy.js` の独立軸は field / industry / occupation / genre / experience / purpose / kind / difficulty / audience / period。旧 job は互換用に保持する。初期分類97件、以前の49件のIDと定義を維持。表示名、別名、内部IDを分離。Ownerが追加・編集・非表示・同軸統合できる。検索は別名・統合先を動的に解決する。

旧jobからの移行は `taxonomy-migration.js`。Ownerが対応先と対象投稿・revision・根拠を確認し、明示同意して適用。25件単位、履歴・監査記録あり、再実行時は適用済みを返す。元ID・本文を消さず、曖昧な職業/業種を推測しない。移行を本番で自動実行しない。

## 検索

語句検索はNFKC正規化、日本語の完全一致境界に `Intl.Segmenter`、引用符による連続句、複数キーワードAND/OR、分類の同軸AND/OR・軸間AND/OR、語句/分類の除外。新着・更新・関連度・Good数・実保存数順。20件ページと条件URLを維持する。正本の現在の公開状態と内容を毎回確認する。Firestoreに全文検索能力があるという表示は行わない。

索引は既存 `posts` から派生したサーバーキャッシュ。上限20,000文書/64MiB、超過時は明示エラー。初回128件ずつ、正本再確認25件ずつ。外部検索契約なし。これは無制限の大規模検索基盤ではなく、現在の明示上限までの実装である。実データ20,000件の負荷試験は未実施。

保存数はcanonical Passportと投稿の組をサーバーで重複防止。旧保存の集計移行もマーカーとロックを使い、再実行・並列・解除で二重加算しない。集計未完了の保存順は503で待機を明示する。

意味検索はGoogleの `gemini-embedding-001`、768次元、RETRIEVAL_QUERY / RETRIEVAL_DOCUMENT。正規化int16で保存し、サーバーでcosine類似度を計算する。固定キーワード拡張で代用しない。モデル変更・本文編集・非公開化・同意撤回を確認し、古いベクトルを結果に出さない。検索文・ベクトルは本文ログに保存せず、クエリキャッシュはPassport別24時間。意味検索は関連度順のみ、明示同意・認証が必要。既存guestの閲覧上限20件は維持する。

過去公開投稿は語句検索対象に含む。外部AIへの同意がない過去投稿は意味検索・AIの対象にしない。新規/編集の同意済み公開投稿をキューへ送り、1分ごと・1回8件、内部索引処理は1日15呼び出しまで。処理遅延・枠不足は翌日へ持ち越す。内部索引処理はAuthアカウント・Passport・活動実績を作らない。Ownerによる初期キュー投入・処理も可能。

## Gemini分析

`gemini.js` / `ai-service.js` / `ai-budget.js` はサーバー側だけ。APIキーは `x-goog-api-key` ヘッダーで送り、URL・エラー・フロント・Gitに出さない。実モデル一覧で対応メソッドを確認する。有料専用等のモデルは除外し、モデルを捏造・自動選択しない。モデル一覧への登場だけで無料利用可能と断定しない。

有効化条件は秘密キー、`GEMINI_FREE_TIER_CONFIRMED=true`、`KNOWLEDGE_LAB_AI_ENABLED=true`、Ownerの無料枠確認・モデル設定・停止解除。Google側の請求先未設定確認が必要。課金の有効化、有料フォールバック、契約は実装/実行しない。Google側の無料上限や対象モデルは変わり得るため実APIで確認する。

利用者が2〜3分野を選ぶ。元知識2〜6件を明示選択、または各分野から20件ずつ最大60候補を検索して同意済み公開知識を最大3件自動取得。不足時は不足と返す。入力は本文先頭3,000文字/件・全体12,000文字以内。どこまで分析したかを表示する。明白なメール・電話・ウォレット・キー文字列を拒否するが、完全匿名化を保証しない。

分野名・公開元投稿のID/題名/本文を送信する。UID・書き手名・Passport・非公開プロフィールはプロンプトに送らない。元資料内の命令を命令として扱わない固定system指示と、外部ツールなしの構成。各主張の元IDと完全一致引用を検証し、架空ID・架空引用・途中出力を拒否する。引用の存在は推論の正しさの保証ではない。

要点・共通点・相違点・意外なつながり・応用・問い・仮説・実践・検証方法・注意点・不明点を構造化表示。全てAIの仮説/未検証。現場での実践結果・第三者確認と分離する。生成ごとに不変の `ai_runs` を残し、キャッシュポインターのみ更新。人の編集、再分析、履歴、手動継続に対応する。

25秒タイムアウト、429/5xxのみ1回再試行。分析10回/日・1Passport3回、埋め込み60呼び出し/日・1Passport15回、同時2件の分散ロック。再試行も枠を消費する。日境界は日本時間。取得済みトークン200,000到達後は新規実行を拒否する。これは未報告トークンも含めた厳密上限やGoogle請求の上限ではない。埋め込みが返さない使用量は未取得と表示し、呼び出し数と入力文字数を記録する。

## 信頼性と循環

第三者確認はOwnerの実際の確認記録があり、現在revisionに一致する場合だけ。自己確認不可、本文編集で失効。詳細根拠と履歴は本人・Ownerだけ、確認範囲の要約/確認者/日時は公開する。AI出力による自動認証はない。

研究→経験知は本人の明示同意を経て既存投稿枠を使う。非公開研究の内容や参照を自動公開しない。公開元研究は現在の公開範囲も検証する。回答→経験知は既存 #195 の本人確認・参照・重複防止を維持。議論・知識募集・Guildの議題→採択→Questは既存操作を再利用し、予算/報酬を追加しない。

活動は投稿・回答・研究作成・研究追記・仮説の実践申告・結果報告・採用された改善案。Passport/種別/対象の組で重複を防ぎ、私用本文を含めない。自分用の活動欄を既存星空に併設し、既存 `sp_stars` の星数、NFT、EMUER、Quest実績は変更しない。実践は自己申告として表示し、実績だけで検証済みとしない。保管後も過去の活動記録は保持する。

## 運営と保護

全新領域は `knowledge_lab_.*` の既存サーバー専用Rulesを適用。新しいRulesや複合インデックスの編集はない。Owner APIは既存 `requireOwner`、一般ユーザーの直接書き込み/閲覧は拒否。正規トークン・Passportから本人性を解決し、クライアントの自己申告は使わない。

運営画面には書き手、投稿、分類、研究、募集、回答、通報、保存集計、検索/0件/不足分野、閲覧、転換、再投稿、継続、AI呼び出し/エラー/キャッシュ/取得済み使用量、索引待機を表示。定義は `analytics.js` の `definition` と運営手順に明記する。過去の未計測行動は推測しない。テストはdemoプロジェクト、本番と同じ集計に混ぜない。

Rules確認は匿名GET/PATCHがPERMISSION_DENIEDになることを各専用領域で検査。失敗時は閉じ、段階・エラーコードのみをログへ出す。秘密値や原文エラーは出さない。Firestore管理API/IAM/ネットワーク/クォータ/後片付けの失敗でも停止するため、停止をRulesの誤りと即断しない。検査に書き込み/削除が発生し、現在の32領域では5分ごとの継続利用で最大約18,432 write/delete操作/日。Firestore既存費用/無料枠を確認する。検査を通すためにRulesを緩和しない。
