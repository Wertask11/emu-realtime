## 現在の状態と、日常運営の入口

- 運営画面：https://schoolpark-emu.vercel.app/?lab=admin 。Ownerだけが管理APIを使える。料金プランや公式パスを購入してもOwnerにはならない。
- 公開投稿・検索・研究：https://schoolpark-emu.vercel.app/?lab=library 。既存の「知識を探す」からも開ける。
- 募集と営業原稿：[書き手募集・営業・広報素材](completion-outreach-draft.md)。紹介・募集・投稿ガイドの実際の公開画面も用意した。DM・メールの外部送信はしていない。
- AI分析と意味検索は共通の無料枠内。モデルは分析 `gemini-3.5-flash-lite`、埋め込み `gemini-embedding-001`。AI Studioの請求先なし・無料枠の確認を維持し、有料へ自動切り替えしない。
- Renderの `KNOWLEDGE_LAB_ENABLED` / `KNOWLEDGE_LAB_AI_ENABLED` / `GEMINI_FREE_TIER_CONFIRMED` は有効と本人確認済み。Firebase管理鍵の交換・旧鍵削除も本人確認済み。再設定や鍵の再共有を日常作業にはしない。
- 新プラン枠は別の [PR #214](https://github.com/Wertask11/emu-realtime/pull/214)。Rules全文の公開はFounderが確認済み。コードのmain反映・配信照合はこの文書更新時点で保留。詳細は [プラン枠の反映状況](../business/membership-capabilities-release.md)。11月1日目標の変更を適用済みとは案内しない。

## 新しい書き手を迎える前の確認

1. Labを開き、投稿・検索・研究を利用できる状態か確認する。障害がある機能を常時使えると募集しない。`/api/knowledge-lab/config` は可用性と保護検査の確認に使えるが、本人操作の代わりにはならない。
2. 運営画面で初期分類・語句索引・保存数集計を確認。既存IDを上書きせず、古いjobの曖昧な対応を推測で一括変換しない。保存数集計はFounderが完了済み。新しい必要性がない限り初期化や再作成を繰り返さない。
3. 意味索引の対象は作者がAI利用に同意した公開知識だけ。初期対象の確認は25件ずつ、登録処理は1回最大8件。無料枠が不足したら翌日へ繰り越す。
4. 投稿者のAI利用同意と、分析・意味検索を実行する人の送信確認を分ける。非公開本文・個人情報・企業の秘密をAIへ送らない。
5. 「経験者に質問する」は、既存の知識募集と同じ募集・回答データ。図書館は既存の投稿を探す場所。見つからない経験を募集し、得た回答を本人が望む範囲で次の知識へつなぐ。
6. 通常の修正では既存の投稿・ログイン・Passport・報酬を維持する。本番と同じデータへ接続するPreviewで保存テストをしない。検証用ユーザー・テスト投稿・実送金を本番へ作らない。

## 最初の10人を招く

募集分野は経営・起業、美容、IT・AI、教育、子育て・家庭、福祉・制度、営業・接客、医療・健康、飲食・店舗、人生・学び直し。1分野1人は募集目安で、実際の参加人数として表示しない。

募集URL→既存ログイン→Passport→経験分野/任意プロフィール→最初の投稿ガイド→下書き→内容/公開範囲を確認→公開。既存ユーザーの再登録は不要。プロフィールは明示保存で端末をまたいで再表示できる。未保存の入力を保存済みと案内しない。

投稿には既存light以上等の利用条件と月間枠が適用される。招待しただけで無料投稿資格が得られるとは説明しない。参加前に既存のプラン条件を知らせる。Founderの判断だけで報酬額・権利枠・NFTを変更しない。

## 毎日・毎週の運営

- 書き手一覧で新規と活動中を確認。プロフィール/職歴/資格は自己申告と実際の確認を区別する。勤務先や本名を要求しない。
- 投稿一覧で公開範囲、経験時期、出典、最終更新、注意点を確認。古い情報は著者に更新を依頼し、勝手に本人の体験を改変しない。
- 分類の追加/別名/統合は内部IDを保持。同軸統合のみ。旧jobの曖昧な対応は保留。
- 検索0件分野と未回答募集から、必要な経験を募集する。0件は利用者が閲覧可能な範囲での結果であり、全体に知識が存在しないと断定しない。
- 研究の出典、未検証仮説、自己申告の実践結果を確認。第三者確認は実際に本人以外として確かめた事項と資料だけを記録する。公開要約と本人/Owner専用の詳細根拠を分ける。自己確認は登録できない。
- 通報を読み、根拠を残して公開停止・復元・注目を操作する。非公開本文はOwner権限のAPIでのみ閲覧。通報者や私用内容を公開しない。
- AIの呼び出し数、取得済みトークン、未報告トークン、入力文字数、エラー、キャッシュ、待機件数を確認。疑わしい出力・費用・モデル変更時は「AI・意味検索を停止」。課金へ切り替えない。
- 研究からの経験知投稿は本人の公開同意が必要。元研究を勝手に公開しない。既存議論・Guild議題→採択→Questへつなぐ場合も既存参加資格・予算・Owner承認を守る。
- 「採用された改善案の実績を確認」は読み取りと正規Passport確認だけ。未確認の旧記録は保留。星空の活動欄は本人専用で、既存の星/NFT/EMUERの追加発行ではない。

## 指標の読み方

サーバー成功処理だけを集計し、本文・人物名・検索文をAnalyticsログへ保存しない。過去の未記録行動は実績から推定しない。エミュレーターと本番をプロジェクトで分離する。

## ロールバック

AIだけの問題ならOwner停止とRender `KNOWLEDGE_LAB_AI_ENABLED=false`。データを消さない。全体停止が必要なら `KNOWLEDGE_LAB_ENABLED=false`。最後に確認済みのVercel/Renderコードへ戻し、新規の保存領域を保持する。旧コードが追加フィールドを読まないことと既存投稿/認証/報酬の回帰を確認する。Labデータが存在する状態で包括許可を開くRulesへ戻さない。新しい秘密鍵への交換はロールバックしない。

旧 #195 の認証・EMUER自己採用防止の修正を取り除かない。本番データ初期化・一括削除・報酬回収・送金は復旧手順に含めない。

## Rules検査の運用補足

検査用固定IDは既存でもユーザー指定を拒否していた。追加版はランダムIDをcreateし、自分が作成成功した文書だけを削除する。既存文書に衝突した場合は閉じ、上書き・削除しない。成功と失敗の再検査間隔は5分。Render Logsの collection/stage/code または httpStatus だけで切り分け、秘密鍵や本文を共有しない。2026-10-14 11:31 UTCの既存版は enabled:true。再発時だけログ確認を行う。

## 実Geminiのローカル検証（模擬応答とは別）

実行環境に安全なGeminiシークレットとGoogle API通信許可を適用し、Google側が無料枠・請求先なしであることを確認した後だけ実行する。キーをコマンド・ログ・チャットへ貼らない。`GEMINI_FREE_TIER_CONFIRMED=true`、`NODE_USE_ENV_PROXY=1` を使い、localhost/127.0.0.1への通信は既存のNO_PROXY設定でローカルのままにする。

1. `NODE_PATH=backend/node_modules node tools/knowledge-lab-tests/live-gemini.cjs --list-models` で実APIのモデル一覧を取得する。課金を有効にせず、実一覧と無料枠からモデルを選び `GEMINI_ANALYSIS_MODEL` を設定する。2026-10-15は `gemini-3.5-flash-lite` の実生成と `gemini-embedding-001` の実埋め込みが成功。`gemini-2.5-flash-lite` は一覧にあっても生成404だったため、一覧だけで利用可と判断しない。
2. 他のエミュレーターテスト/ブラウザーを止めてから `NODE_PATH=backend/node_modules node tools/knowledge-lab-tests/live-gemini.cjs` を実行する。Auth9199/Firestore8787、demoプロジェクトだけを使う。他のローカル検証との同時実行を避ける。ドライバーは使用量・データを消さない。上限に達した際、リセットやアカウント変更で回避せず待機する。
3. 明示的に架空ケースと表示したローカル投稿3件を作成し、実Gemini分析、出典検証、私用研究保存/編集/履歴、実埋め込み索引、日本語意味検索の順位を確認する。通常は分析1回・索引1RPC・検索1RPCで、既存の回数/再試行制限が適用される。定期処理はこの検証内で止める。
4. 成功した実結果のみ `/workspace/outputs/knowledge-lab-completion/live-gemini/results.json` へ保存する。秘密値、認証ヘッダー、実ユーザー本文は出力しない。失敗はコードだけ報告し、固定応答へ置き換えない。

この検証が成功しても、本番利用者の実体験を分析できた証拠や意味検索全体の品質証明ではない。本番で作者/利用者の同意、出典の正しさ、無料枠、保存/更新、既存回帰を別途確認してからREADYとする。2026-10-15には設定反映後の実API成功まで確認済み。

## 開発・公開を続ける場合

RulesはFounderの手動運用。追加変更がある場合は最新の全文を比較し、適用日・権利・アクセス上限をEmulatorで検証する。保護検査が `RULES_NOT_VERIFIED` なら、Rules・IAM・クォータ・ネットワーク・検査の後片付けを切り分け、許可を広げて通さない。

本番公開は差分レビュー→自動/Emulator/ブラウザ/Preview→必要な本人設定→main反映→Vercel静的ファイルとRender `config.releaseCommit` の照合→本番確認の順。既存の有効なAIを、古い初回公開手順の指示だけで無効化しない。

未実施の実践結果→派生投稿→星空の本番本人確認などは [25項目表](production-founder-verification-2026-10-15.md) へ追記する。未確認事項を過去のローカル成功で埋めず、すべての証拠が揃ってから全機能READYとする。
