# AI_INVALID_CITATION の修正（2026-10-15）

本番でGemini分析が `502 AI_INVALID_CITATION` となり、研究フォームへ入力されなかった。従来はモデルが生成した引用文の完全一致を要求していたため、日本語の言い換え・表記変更も全分析の拒否につながる。実際に失敗したモデル出力は保持していないので、どの引用が違ったかは未確定。

## 変更

- サーバーが許可済みの公開投稿から連続した原文を最大200コードポイントずつ切り出し、参照番号を付ける。自然な区切りを優先し、短文の多い投稿でも参照番号数を制限する。
- Geminiは本文の転記をせず、`sourceId` と `evidenceId` を構造化出力で選ぶ。サーバーが対応表から引用原文を復元する。
- 存在しない番号、別投稿の番号、モデルが付加した引用文は拒否。復元後にも既存の元投稿完全一致・全資料の要約・仮説と注意事項の検査を実行する。
- 保存・表示の `{sourceId, quote}` 形式は維持。新規キャッシュは `analysis-v2-evidence-ids` へ更新し、過去の研究ノート・履歴は変更しない。
- 無料枠、同意、Passport所有権、公開範囲、Owner停止、APIキー保管、EMUER、Camelliaは変更しない。Firestore移行・Rules・追加環境設定は不要。

## 検証

- 単体・API設定・プロバイダー障害分類: 13 PASS。架空番号、別投稿、AIによる引用転記、原文改変、長文・絵文字のテストを含む。
- Auth / FirestoreエミュレーターのAI・意味検索・保存・知識循環: 39 PASS。モック用プロジェクト `demo-emu-knowledge-lab-analysis-ui` に隔離した。
- 実Gemini `gemini-3.5-flash-lite`: 明示したローカル架空ケース2件で1回の分析が成功。20件の引用を元文章と完全一致で照合。605入力 + 1801出力 = 2406報告トークン。
- 実出力を非公開ノートへ保存・読み戻し、別Passportの404、再要求のキャッシュ利用・追加推論なしを検証した。
- 以前のエミュレーターデータは現プロセスに残っていなかったため、保管済み実API検証記録から同日使用量の下限（全体分析5回、alice3回、bob2回）を単調増加で復元し、同じbobで1回だけ実行。既存カウンターを減らす処理はない。アカウント切替や本番上限の変更はしていない。

- Chromiumで実Geminiの保存済み結果を本人の非公開ノートから開き、20引用の表示・編集保存、375 / 390 / 412 / 768 / 1024 / 1366pxで横はみ出し・JS例外なしを確認。追加推論は行っていない。
- 実Auth・Firestoreと模擬プロバイダーを用いた画面テストで、同意拒否・進行表示・重複実行防止・③への自動入力と保存も確認。これは実Gemini推論の証拠とは分ける。

実API・ブラウザー証拠は `/workspace/outputs/knowledge-lab-citation-fix/`。検証用の架空ケースとローカル画面であり、実ユーザー投稿を使った本番成功の証明とは区別する。本番のユーザー操作の成功は別途必要。
