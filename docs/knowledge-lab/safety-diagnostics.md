# Knowledge Lab安全検査の診断修正

既存Productionの`RULES_NOT_VERIFIED`が一時復帰後に再発した。旧コードは原因を返さず、失敗直後の再リクエストでも検査用書き込みを再実行していた。今回の変更は既存版の安全ゲートを保ったまま、原因と再検査時刻を確認できるようにする。AI・高度検索の正式公開とは別の修正。

## 変更

- `/api/knowledge-lab/config`の` safetyCheck `に段階、許可したエラーコード、確認時刻、再検査までの秒数を追加。生のエラー文、秘密値、認証ヘッダー、本文、ユーザーIDは返さない。
- 成功・失敗とも検査結果を最大5分保持。失敗直後の連続書き込みを防ぎ、時間経過後のリクエストで再検査する。
- ランダムIDの`create`を使い、既存文書を上書きしない。作成成功が確認できた自分の検査文書だけを削除する。
- 後片付け失敗時は閉じた状態を維持する。次の検査で自分の文書の後片付けを先に再試行し、新しい検査文書を増やし続けない。
- Rules判定の条件、14領域、認証、Owner、EMUER、既存利用資格・保存処理は変更しない。Rules/インデックス/フロントエンド変更、データ移行はない。

## 原因の読み方

|段階/コード|確認するもの|
|---|---|
|firebase-init / DB_UNAVAILABLE|RenderのFirebase初期化設定。FIREBASE_PROJECT_IDの省略だけを異常と決めない|
|admin-probe-write / 7|Firestore管理SDKの権限・IAM|
|admin-probe-write / 16|管理SDKの認証・鍵の有効性。必要ならRenderの管理鍵を安全に交換|
|8|Firestoreの利用枠・クォータ。課金を自動有効化しない|
|4 / 14 / ネットワークコード|タイムアウト・サービス/通信障害|
|anonymous-access-check / UNEXPECTED_RULES_RESPONSE|匿名アクセスが想定の403/PERMISSION_DENIEDでなかった。httpStatusを確認。200なら保護を確認するまで開放しない|
|cleanup|自分の検査文書の削除失敗。権限/通信を確認し、ゲートを迂回しない|

この検査は匿名アクセスの確認で、認証済み他ユーザーの権限検証やRules全文の確認の代わりにはならない。ローカルRules/認証テストと本番の本人操作は別の証拠として扱う。

## 本番タイムアウトへの通信修正

診断版63fd3eeの本番応答で、管理SDKによる作成後の匿名アクセス検査が`ETIMEDOUT`（writers）で止まることを確認した。IPv6が原因だとは断定しない。

同時検査を2領域（匿名GET/PATCHは最大4件）に制限し、1件失敗した後は新しい検査を始めない。未検査の領域は成功に数えず、全14領域が成功した場合だけ開く。直接HTTPSの匿名検査にはIPv4と最大4接続の再利用を使う。プロキシ設定があれば既存fetch経路を維持し、エミュレーターも従来のloopback fetchを使う。TLS検証を有効に保ち、秘密鍵・APIキー・ユーザー本文を検査へ送らない。応答は100KB、通信は6秒に制限。

通信修正の追加7テストと、全50件Lab/API/RulesがPASS。既存349件Backend・174件Emu/ガイドと合わせ573件。個別のtransport/guard最終確認12件もPASS。実際のRenderで成功するかは反映後のconfigで確認し、ローカルの模擬ソケット成功だけで復旧と報告しない。

## 検証

43件Lab/API/Rules、349件Backend、174件Emu/ガイド、計566件PASS・失敗0・skip0。追加5件は失敗時の閉鎖/間隔、衝突時の既存記録保持、安全な公開診断、後片付けの失敗/復旧、ネットワーク原因の安全な診断。

実ネイティブUIとAuth/Firestoreエミュレーターで、書き手・投稿・回答公開・検索・保存・研究の更新/履歴/保管/再ログイン/復元/編集・Owner操作を確認。ページ例外0。Productionへ検証用ユーザー/データは作成していない。証拠は`/workspace/outputs/knowledge-lab-safety-hotfix/`。

## リリースと戻し方

main反映後、Vercelの成功状態とRenderの`releaseCommit`を確認する。実際のconfig応答で原因を読み、根本の設定/通信/権限を解消する。ビルド成功だけで本番復旧や全機能READYとはしない。追加版PR #196は別途、実Gemini/意味検索・本番統合の公開条件を満たすまで未公開。

問題が出た場合は`KNOWLEDGE_LAB_ENABLED=false`で保存済みデータを保護し、修正コミットをrevertして確認済みコードへ戻す。Rulesを緩めたり本番データを削除/初期化したりしない。管理鍵の交換を元の公開済み鍵へ戻さない。
