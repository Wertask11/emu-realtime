# 本人の公開投稿が一覧に出ない問題

`/me/public-posts` は `authorSchoolParkId` だけで検索しており、そのフィールドがない従来Emu投稿が本人の一覧から漏れていた。認証済みアカウントのウォレット／CHESアドレスの既存表記・小文字・チェックサム表記も、従来のaddress／owner／authorから検索する。FirestoreのORクエリで文書ID順21件までを取得し、20件単位でページ送りする。全投稿走査・移行・複製はしない。

取得後は詳細／編集と同じ本人判定と公開判定を使う。別Passportが明記された投稿は、旧アドレスが一致しても本人扱いしない。Owner権限を本人扱いの根拠にせず、非公開・保管済み投稿を一覧に出さない。任意のアドレスをクライアントから受け付けない。

マイライブラリーの切り替えにも応答順序のガードを追加した。保存一覧の遅い応答が、その後選んだ公開投稿一覧を空欄で上書きしない。

## 検証

- 実Auth／Firestoreエミュレーターの回帰4件PASS。旧小文字／チェックサム／CHES／owner／authorとPassport投稿の同時取得、別Passport・他人・非公開・保管済み除外、Owner本人範囲、旧投稿IDを維持した編集、重複のない31件ページ送り、未ログイン401を確認。
- 実ブラウザ：旧投稿を公開一覧で表示→編集→分野・本人による任意AI同意→同じIDへ保存→再ログイン→一覧再表示。他人の一覧への混入なし。保存一覧の実応答を保留して公開一覧の後に返しても、公開一覧が保持されることを確認。
- 375／390／412／768／1024／1366px、横はみ出しなし、ページ例外0。証拠は `/workspace/outputs/knowledge-lab-legacy-public/browser-results.json` と `LOCAL-legacy-public-*.png`。
- 構文・リンク・JSON・重複ID・差分検査PASS。Firebase Rules、インデックス、依存ライブラリ、root index.html、Camellia、EMUER処理は変更なし。
- テストはローカルエミュレーターだけ。過去の実Gemini記録を消すリセットや本番データへの書き込み、外部AI呼び出しを行っていない。
