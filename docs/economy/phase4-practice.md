# 冷蔵庫くんに頼む — 実践と記録

2026-11-09。無料の手動操作を実装。決済・生成・返却・Knowledge Lab本体は変更しない。最終検証結果は末尾に記載する。

## 操作

1. 冷蔵庫くん →「頼む」→ 保存した下書き・計画 →「やってみる（追加料金なし）」。5種類に対応。旧形式にチェック項目がなければ本人が1行1項目で入力する。過去の成果物を再生成しない。
2. 未着手／進行中／完了／保留を選び、項目メモ・実際の行動・方法・結果・失敗・気づき・次の行動を入力。「保存・再送」で保存する。
3. 一時中断・再開・完了・中止。未完了の項目がある完了操作は確認する。本人操作なしに完了・参加を実行しない。
4. 本人が振り返り・投稿タイトル・アドバイスを記入する。未記入は明示し、実体験や感想を補わない。
5. 事実・個人情報・権利を投稿前に確認 →「投稿用の文章をコピー」→「投稿画面を開く」。既存Knowledge Lab入口で本人が貼付・編集・公開する。本文をURLへ入れず、自動入力・公開もしない。
6. 「実践記録を開く」で保存済み記録を再表示。一覧は本人の期限内の20件まで。元計画から再度「やってみる」を押しても同じ記録を開く。

## データとAPI

- `emuer_v2_agent_practice/{hash(uid,spid,artifactId)[0:40]}`：ownerUid、spid（SchoolPark ID）、sourceArtifactId、sessionId、artifactType、status、checklistItems、progress、notes、observations、reflections、postTitle、advice、postingChecks、createdAt、updatedAt、completedAt、deleteAfterMs、revision、直近操作の冪等情報。
- `emuer_v2_agent_practice_owners/{hash(uid)}/items/{sessionId}`：本人一覧用の最小索引。全体走査・一覧各行の元資料取得を行わない。
- `POST /api/economy/practice`：本人の有効な成果物から開始。原本の成果物・ジョブ・台帳は変更しない。
- `GET /practice`、`GET /practice/:id`、`POST /practice/:id`（全て`/api/economy`配下）。更新はrevisionとrequestIdが必須。古い版・同じキーで異なる内容は409。同一操作の再送は版を増やさず返す。
- owner・進捗・日時・期限をクライアントに書き換えさせない。本人が送った状態からサーバーで進捗・実施日時を計算する。
- 元計画本文・生成された実践結果は実践記録へ複製しない。生成チェック項目はIDで保持し、表示時に現行の本人所有・決済済み成果物と許諾を確認。手動項目とメモは本人入力。

## 権限・料金・許諾

全経路で既存Firebase認証・SchoolPark ID・現在のPlus/Pro会員情報・提供資格を使用。Free/Light、期限切れ、他人のUID/SchoolPark IDは拒否する。既存Rulesの`emuer_v2_.*`拒否で2領域ともクライアントの直接読書きを禁止し、検証済みAPIに限定する。Rulesの変更・公開は不要。

新規生成は引き続き5 EMUER、本人3／全体20件/日・同時2件、5,000予約tokens/件・100,000/日、Gemini無料枠。実践開始・チェック・記録・手動振り返り・整理・コピーは0 EMUER。Phase 4には決済・モデル・外部送信の依存がなく、追加生成は提供しない（`additionalGenerationEnabled:false`）。自動投稿・参加・購入・交換・送金はない。

資料の削除・内容変更・許諾撤回・期限切れ時は元計画・参照元を表示せず、元資料に基づくチェック状態の変更を拒否する。本人入力のメモ・振り返りは別管理で、資格・保存期限内なら閲覧・編集できる。投稿用文章は本人の記録だけから整形する。

## 保存・通信断

開始から30日。更新で延長しない。期限後は読書きを拒否し、既存workerの毎時cleanupで最大100件ずつ本文と本人索引を削除。障害中は遅れ、復旧後に再開する。既存の目的・結果30日方針に合わせ、画面・Privacyに明記。取引・既存成果物の期限は変更しない。

未保存入力は本人・記録別のsessionStorageに最大2時間。同じタブの再読込で復元し、保存成功・アカウント切替・ログアウト時に対象を消去。端末内タイマーも期限時に消去する。端末の保存拒否を通知する。別端末への同期・タブ終了後の復旧は保証しない。

保存応答が失われても同じrequestIdで再送可能。別画面で新しい版がある場合は以前の入力を復元欄に示し、本人が照合する。自動上書きしない。保存中は入力をロックし、応答で追加入力を消さない。

## 負荷・停止

実践専用のポーリング・リスナー・全件走査はない。本人の開始・一覧表示・取得・保存・コピー時だけ読み取る。文字入力は端末保存のみ。元資料の再検証には必要な資料だけを読む。

毎時cleanupに索引付き期限クエリ1本を追加（空なら約24読取/日）。期限分だけ最大100件を削除する。元成果物の確認には既存の会員・資格・ジョブ・注文・資料確認も必要で、API1回をFirestore1読取とは扱わない。現在の日次残量は利用可能なAPIから取得できず、Firebase Consoleで確認する。

停止は`ECONOMY_PHASE4_ENABLED=false`でRender再配備。Phase 2/3・既払ジョブ・返却用workerは止めず、本人記録の移行・削除をしない。定期cleanupは継続。再開はtrue。コード既定値はOFF。
