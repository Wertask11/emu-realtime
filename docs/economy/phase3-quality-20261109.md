## 原因と修正

旧 `tasks.js` は全作業を5つの `prompt` に限定し、各220字・指示/質問の文末を要求していた。保存・参照・権限・支払いは確認できても、候補比較やチェックリストそのものを作成したかを確認していなかった。

`tasks.js` から構造化成果物の `work-artifact.js` に委譲し、生成とサーバー検証を更新した。料金・商品・台帳・worker・プラン判定・返却の処理は再利用する。

- `title / summary / candidates / steps / checklist / evidence / unknowns / reflection` を保存。Knowledge/WILには本文 `draft` を持つ。作業ごとに必要な候補種別を限定する。
- 候補は確認済みの実資料だけ。推奨候補は単一の `recommendedKey` を検証して復元し、独立した真偽値の取り違いを防ぐ。Quest/Guild/Cityは比較可能な資料が複数あれば2件、1件なら架空候補を増やさず単一候補とする。投稿/WILは関連する資料1件から利用可能。
- 3〜7件の順番付き手順と各完了条件、5〜8件の個別チェック項目、根拠、未確認事項、実践後の記録を検証する。同じ文の繰り返し、抽象的な丸投げだけの指示、存在しないID/URLを拒否する。
- 候補名・正規リンク・公開説明・価格・在庫・期限はサーバーが現行資料から復元する。AIが価格・日付・難易度・参加資格を断定する出力は拒否する。難易度の根拠がない場合や、目的の技術実習が確認できない場合は未確認として表示する。
- 本人の実体験は空欄。本文には4箇所以上の本人記入欄と十分な文章量を要求し、その外側で実績や効果を過去形で作る出力を拒否する。公式ガイドの「こんな状況でした：［本人記入：…］」という項目名は経験の断定ではないため、直後が明示的な空欄である場合のみ区別する。空欄外の捏造実績は引き続き拒否する。WILには独立した学習目標・具体的な準備物を要求し、実践前/中/後ごとの日時・方法・観察・次の条件がある記録シートを成果物として作成する。「準備物リストを作る」とだけ返す出力は拒否する。具体的な実践・観察行動を必要とし、コーヒーなら香り/見た目等の観察対象を検証する。
- 投稿/WILの生成資料から、目的と無関係なプラン紹介や操作メニューを外す。案内資料しか確認できない状況では、専門的な技法や数値を創作せず準備・観察の提案と未確認事項を分ける。

自然言語の意味全体を形式的に証明するものではない。機械検証に加え、下記5件の実出力を候補・手順・チェック項目・本人実績の扱いについて確認した。元資料自体にない技術講座や協力店舗を提供済みとは扱わない。

## 保存・本人確認・旧形式

既存の本人専用成果物に `formatVersion: 2 / document / checkedItems` を追加する。新コレクション、Rules変更、データ移行はない。チェック操作は既存編集APIで明示的に保存し、所有者・有効なPlus/Pro・提供資格・許諾・revisionを確認する。保存時の追加AI実行/決済はない。

文面の編集と生成時の構造化計画は区別して表示する。コピーには本文・保存済みチェック状態・再確認済み出典を含む。未保存の本文があるときはチェック保存によって失わないよう案内する。許諾失効時は比較・手順・チェック状態も隠し、アカウント変更時は表示を消去する。

旧形式はそのまま表示・編集・コピー可能。勝手な変換や再生成をしない。旧クライアントにも `content` を維持する。30日削除では新しい構造化本文とチェック状態も消去する。
