# Emu プラン最終仕様（無料見学 / light / plus / pro）

最終更新: 2026-08-17 / 決定: オーナー（合同会社型DAO SchoolPark 代表）

商品は3つ。その手前に「無料見学モード」を置き、全体で4段階にする。
無料見学は商品ではなく、店内を見て回る入口。

| 段階 | 価格 | 役割 |
|---|---|---|
| 無料見学モード | 0円 | Emu が何かを理解する |
| Emu light | 月額 500円 | 知識交換を1回体験する |
| Emu plus | 月額 3,000円 | 学びを継続・蓄積する |
| Emu pro | 月額 10,000円 | 契約済みの対話機会を通じて前進する |

### light の仕事は一つだけ

> **自分の経験や問いを初めて外へ出し、運営から受領の反応を受け取る。**

約束するのは「運営が投稿を読み、受け取ったことを短いコメントで伝える」まで。
**「考えが変わる」「必ず役に立つ」「仲間が見つかる」は保証しない。**

受領コメントの例：
> あなたの経験を受け取りました。特に「〇〇」という部分は、
> 同じ状況にいる人が考えるきっかけになりそうです。

この仕組みは**初期100人限定**。人数が増えたら提供方法と担当体制を再設計する。

### pro は公開済みの契約を維持する

いま規約・保証・特商法に書いてある内容から**足さない**。
安全対策と本人確認を整えるまで、コミュニティ機能を pro の商品として約束しない。

**宣伝で使わない表現**：マッチング／専門家と必ず話せる／仲間が見つかる／
プロジェクトメンバーが集まる／成果が出る／人生が変わる

## 2. 既存ユーザーの扱い（Founding Emuer）

既存ユーザーから突然機能を奪わない。

- 施行日より前から使っている人を **Founding Emuer** とし、**一定期間 light を無償提供**する（6か月案。3か月でも可）
- 新規ユーザーは無料見学モードから開始
- 変更内容と適用日を**事前通知**（規約 第10条の14日前告知を最低限守る）
- 移行期間の終了前に、続けるプランを**本人が選ぶ**
- **自動で有料契約へ切り替えない。決済登録していない人へ自動請求しない**

判定は `ches_accounts.createdAt`（全ログイン方法で記録あり）を使う。

## 3. 実装項目

### ★ 最優先：利用資格（エンタイトルメント）の共通化

**これを最初に作らないと、他が何も作れない。**

いまプランで機能を出し分ける仕組みは1つもない。有料判定は NFT 所有を見ており、
Stripe のプランとは無関係。`/api/billing/status` はバッジを出しているだけ。

さらに **Founding Emuer は Stripe を通さずに light 相当を得る**ため、
「Stripe のプランを読む」だけでは足りない。

必要なもの：

| # | 内容 | 重さ |
|---|---|---|
| 1 | サーバー側 `getEntitlement(uid)` … Stripe のプラン **または** Founding 付与から、`guest / light / plus / pro` を返す | 小 |
| 2 | サーバー側 `requirePlan(['light','plus','pro'])` ミドルウェア | 小 |
| 3 | フロント側 `window.emuEntitlement` … `/api/billing/status` の結果を一度だけ取り、各 iframe へ渡す既存パターン（`canDraft` / `canSchedule`）に相乗り | 小 |
| 4 | Firestore ルール側の判定 … 知識の投稿・募集はサーバーAPIを通らずルールだけで動いているため、ここにも資格判定が要る | 中 |

## 4. 残る論点（要判断）

1. **受領コメントの書き方**。「月1回まで」は上限の表現だが、利用者は約束と読む。
   提供できなかった月は未提供＝返金対象になりうる（法務部）。
   「原則として」「〇営業日を目安に」といった書き方にするか要検討。
2. **Founding Emuer の期間**（6か月 / 3か月）と、**終了時に一斉離脱が起きる**risk への備え。
3. **light の月1件は少なすぎないか**。「初めて外へ出す」体験としては十分だが、
   2か月目以降に続ける理由が弱い可能性。plus への転換で回収する設計になっている。
4. 無料見学の**遊びの回数制限**を、端末側で数えるか、サーバーで数えるか。
