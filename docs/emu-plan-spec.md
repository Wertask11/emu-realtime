# Emu プラン仕様 v1.0（無料見学 / light / plus / pro）

最終更新: 2026-08-17 / 決定: オーナー（合同会社型DAO SchoolPark 代表）

> v1.0。v0.9 で残っていた項目はすべて確定・実装した。
> 実装との差が出たら、こちらではなくコードを正とし、この文書を直すこと。

商品は3つ。その手前に「無料見学モード」を置き、全体で4段階にする。
無料見学は商品ではなく、店内を見て回る入口。

| 段階 | 価格 | 役割 |
|---|---|---|
| 無料見学モード | 0円 | Emu が何かを理解する |
| Emu light | 月額 500円 | 知識交換を1回体験する |
| Emu plus | 月額 3,000円 | 学びを継続・蓄積する |
| Emu pro | 月額 10,000円 | 契約済みの対話機会を通じて前進する |

**商品階段の言い方（確定）**：体験する → 継続・蓄積する → 対話で前進する

## 1. 上限の数字 ★確定（2026-08-17）

「拡張」という言葉は使わない。顧客にも開発者にも意味が確定せず、規約にも書けないため。

| 機能 | 見学 | light | plus / pro |
|---|:--:|:--:|:--:|
| 知識を届ける（投稿） | 0 | **月2件** | **月30件** |
| 知識を募集する | 0 | **月1件** | **月10件** |
| 募集へ回答する | 0 | **月5件** | **月30件** |
| 一日シェアを記録する | 0 | **月7日** | **毎日** |
| 議論を作成する | 0 | **なし** | **月10件** |
| マイライブラリー | 0 | **30件** | **1,000件** |

**「無制限」は使わない。** 十分に大きい上限のほうが、荒らし・自動投稿・想定外のコストを防げる。
（マイライブラリーも例外にしない。1,000件は実質無制限だが、上限があること自体が防壁になる）

### ★ 期間の数え方（確定）

上限の「月」は**暦月ではなく請求期間**とする。

> **契約開始日から、次回更新日の前日まで**

暦月にすると、月末に入会した人が翌日に上限が復活してしまう。

### light の月2件について

light の仕事は「1回体験する」だが、顧客には**もう一度試して確かめる余裕**が要る。
1回目で投稿の仕方を覚え、**2回目で価値を実感する**。この二段階が現実的。
月1件だと、一度うまくいかなかった時点で終わってしまう。

### pro は機能表の一列ではない

pro は plus の上位グレードではなく、**別カテゴリ**。
販売画面では機能表を plus で終わらせ、pro はその下に別枠で置く。

> **Emu pro** — plus のすべてに加えて、当社が選定した対話相手との対話機会が
> 30日間で4回以上。所定の条件を満たしても継続して対話したい相手が
> 一人もいなかった場合、初月料金を返金します。

**宣伝で使わない表現**：マッチング／専門家と必ず話せる／仲間が見つかる／
プロジェクトメンバーが集まる／成果が出る／人生が変わる

## 3. 運営の受領コメント ★確定（2026-08-17）

**曖昧な言葉を混ぜない。**「月1回まで」「原則として」「目安」を並べると、
顧客には保証に見え、運営には努力義務に見える。危険なので、条件で書く。

> **light 以上の会員は、請求期間中に1件の投稿を「運営確認を希望する」として指定できます。
> 運営は指定日から7営業日以内に、受領コメントを1回返します。**

### 条件

- **希望制**。利用者が「運営確認を希望する」を押した投稿だけが対象
- **自動的に全投稿を確認対象にしない**
- 1請求期間につき1件
- 禁止事項に該当する投稿は対象外
- 投稿を削除した場合は対象外
- **内容の正しさや成果は保証しない**
- コメントは受領と着眼点を伝えるもので、**専門的な助言ではない**

### 未提供時の補償

7営業日以内に提供できなかった場合、**翌月の light 料金相当（500円）を割引する**。

> 決済処理・規約・会計との整合は専門家の確認が必要（未確認）。

### 人数の上限

**先着100名まで。** 商品ページにも明示する。

> 運営の受領コメント付きの light は先着100名まで。

101人目から**内容が変わる設計にはしない**。受付停止、または別商品を提示する。
（表示と実数を一致させる運用ルールが要る。§29 の「実数のみ」に従う）

## 4. pro の保証 ★確定（2026-08-17）

**「30日間で最低4回の対話機会」と「語り合える一人保証」は別物。**
「4回案内したが、語り合える一人とは感じられなかった」というケースが必ず起きる。

感情ではなく**条件で判定できる形**へ寄せる。案：

> 当社が選定した対話相手との対話機会を、初回30日間に4回提供します。
> 所定の条件を満たして4回の対話機会を利用しても、継続して対話したい相手が
> 一人もいなかった場合、初月料金を返金します。

### 対話機会の内容（すべて確定・規約 第5条の3 と保証ページに記載済み）

| 項目 | 決めたこと |
|---|---|
| 形式 | **1対1**。複数人での実施は対話機会に含まない |
| 方法 | オンラインの**音声または映像**。文字だけのやりとりは含まない |
| 1回の時間 | **30分以上** |
| 日程 | 各回**2つ以上の候補**を提示する |
| 利用者が来なかった場合 | 連絡なしの欠席は参加回数に数えない。事前連絡があれば代わりの日程を1回提示 |
| 当社の都合で開けなかった場合 | 提供回数に数えない。代わりを提示する。**4回に満たなくても利用者は不利にならない** |
| 「語り合える」の判定 | 対話後の**本人の評価**による。気持ちの証明は求めない |
| 返金申請期限 | 入会31日目から7日間 |
| 全額返金の対象 | 初月料金 |
| 一人あたり | 初回入会時の1回限り |

> 保証の内容と返金額は変えていない。運用の具体を書き足しただけだが、
> 公開済みの契約に触れるため、2026-08-17 の掲示に含めて 9/1 発効とした。

## 5. 利用資格（エンタイトルメント）★実装済み

### 実装済み

- `backend/entitlement.js` … `getEntitlement(uid)` と `requirePlan(min)`
- 契約（Stripe）と付与（Founding）の両方を見て、上の段を採る
- 支払い遅延（past_due）では締め出さない
- 契約が変わったらキャッシュを捨てる

### ★ 判定の正はサーバーにある

`window.emuEntitlement` は**表示のためだけ**の情報。利用者がブラウザ上で書き換えられる。
**セキュリティには使えない。**

| 層 | 判定の正 |
|---|---|
| サーバーAPI | サーバー側で `requirePlan` により判定 |
| Firestore への書き込み | Firestore ルール、またはサーバー経由で判定 |
| 画面 | **ボタンを隠すためだけ**に利用 |
| 契約の反映 | Stripe Webhook（開始・変更・解約・支払失敗） |
| Founding の付与 | **運営だけが書き換えられるレコード** |

### 付与は「施行時に確定するレコード」（実装済み）

`ches_accounts.createdAt` から毎回その場で判定するのはやめた。
基準日が変わったりデータが揺れたときに、誰にいつ何を渡したのかを追えないため。

```
entitlements/{uid}
  plan: "light"
  source: "founding"
  startsAt: ...
  expiresAt: ...
  grantedBy: "migration-2026"
```

Firestore ルールで**クライアントからは読み取り専用**にする。

## 6. 一日シェアの保存30日 ★確定（2026-08-17）

**削除しない。閲覧できなくなるだけにする。**

> 30日を超えた記録は light では閲覧できなくなるが、一定期間は保持し、
> plus へ変更すると再表示される。

**保持は記録日から1年間**（プライバシーポリシー 第3条・第7条に記載済み）。
1年を過ぎたら削除する。永久に隠して持ち続けることはしない。

画面には「30日より前の記録が◯日ぶんあります。Emu plus 以上で、また見られるようになります」と出す。
黙って消えたように見せない。

- **自動で有料契約へ切り替えない。決済登録していない人へ自動請求しない**
- 規約 第10条の14日前告知を最低限守る（2026-08-17 掲示済み）

## 8. EMUER について ★方針確定

light 以上で EMUER 交換を可能にすることは、**プラン設計とは別に慎重な確認が要る**。

- 交換条件 / ウォレット必須か / ガス代の負担
- 未成年者の扱い
- アプリ内ポイントと暗号資産の表示区別
- 価格や利益を期待させない説明
- 本人確認等の必要性

> **「500円を払えば暗号資産を受け取れる」という見え方になると、
> 本来の学びではなく金銭目的の顧客が流入する。**
> 広告で EMUER を前面に出さない方針を維持する（§32）。
