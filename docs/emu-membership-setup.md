## 1. Firebase：メールログインを有効化

Firebase コンソール（<https://console.firebase.google.com/> → プロジェクト `emusch-2a111`）:

1. 左メニューの **構築 → Authentication** を開く
2. 上部の **Sign-in method** タブを開く
3. プロバイダ一覧から **「メール / パスワード」** を選ぶ
   （すでに有効な場合は、行の右端の鉛筆アイコンから編集画面へ）
4. 編集画面に **トグルが2つ**あります。**両方をオンにする**
   - 「メール / パスワード」… 有効にする
   - **「メールリンク（パスワードなしでログイン）」… 有効にする** ← これが本命
5. **保存** をクリック

> パスワード認証は使いませんが、Firebase の仕様上、メールリンクはこのプロバイダの
> 配下にあるため、親のトグルもオンにする必要があります。

6. **Authentication → Settings → 承認済みドメイン** に `schoolpark-emu.vercel.app` が
   入っていることを確認する（無ければ「ドメインを追加」）

> **間違えやすい点**: 「テンプレート」タブ（URL が `/authentication/emails`）はメール本文の
> 編集画面で、ここでは有効化できません。**Sign-in method** タブ（`/authentication/providers`）です。

7. **テンプレート**タブ → 左下の **テンプレート言語** を **日本語** にする
   （既定は英語で、ログイン用メールが英語のまま届きます）

送信元は初期状態で `noreply@emusch-2a111.firebaseapp.com` です。これで動きますが、
迷惑メールに振り分けられやすいので、「届かない」という声が出たら
テンプレートタブの **SMTP 設定** から独自ドメインの送信サーバーに切り替えてください。

**確認方法**: 本番サイトのログイン画面で「メールではじめる」→ 自分のアドレスを入れて送信。
「ログイン用のリンクを◯◯に送りました」と出て、実際にメールが届けば成功です。

| 出たエラー | 原因 |
|---|---|
| メールログインが Firebase で未有効です | 手順4のトグルが入っていない（`auth/operation-not-allowed`）|
| このドメインが承認済みドメインに未登録です | 手順6が未実施（`auth/unauthorized-continue-uri`）|

> 届いたメールのリンクを開くと `?oobCode=...` 付きで戻ってきて、自動でログインします。
> 別の端末でリンクを開いた場合は、確認のためメールアドレスの再入力を求めます。

## 2. Stripe：アカウントと商品の作成（**オーナー自身の作業**）

私（Claude）は金融情報の入力とアカウント開設ができません。ここはご自身で行ってください。

### ★ 最重要：テストモードと本番モードは別世界

Stripe は**テストモードと本番モードで、商品・価格・Webhook・APIキーがすべて別物**です。
テストモードで作ったものは本番に一切引き継がれません。**2-2 以降を2回やることになります。**

推奨する順番：

```
1周目（テストモード）… 事業者の有効化は不要。すぐ始められる
  商品・価格を作る → ポータル有効化 → Webhook作成 → sk_test_ を Render に入れる
  → カード 4242 4242 4242 4242 で通しで確認（5-3）
        ↓ 全部通ったら
2周目（本番モード）… 事業者情報と銀行口座の登録・審査が必要
  同じものを本番モードで作り直す → sk_live_ に差し替え → 少額で最終確認
```

**テストモードは事業者の有効化なしで今すぐ使えます。** 審査を待つ間にテストを済ませてください。
画面右上（または左上）の**「テスト環境」トグル**で切り替えます。

### 2-1. アカウント作成と本番有効化

1. <https://dashboard.stripe.com/register> でアカウントを作成（済）
2. **まずはテストモードのまま 2-2 へ進む。**
3. テストが全部通ってから、事業者情報・銀行口座を登録し、**本番の有効化（Activate）を完了**する
   - 合同会社型DAO SchoolPark として登録
   - 代表者の本人確認書類の提出が必要
   - 審査に数営業日かかることがある

### 2-2. 商品と価格を作る

1. ダッシュボード上部の **カタログ（Product catalog）** を開く
2. 右上の **「商品を追加」**
3. 入力する
   - 商品名: `Emu 有料会員`
   - 料金体系: **定期的（Recurring）** ← ここを「一括」にしないこと
   - 金額: **10000**、通貨: **JPY**
   - 請求期間: **月次**
4. 保存すると価格が作られます。価格の詳細を開き、
   **価格ID（`price_` で始まる文字列）をコピーして控える**

### 2-3. カスタマーポータルを有効化（解約導線）

1. **設定（歯車アイコン）→ Billing → カスタマーポータル**
2. 機能の中で次をオンにする
   - **「サブスクリプションのキャンセル」** ← これが会員の解約導線になります
   - 「支払い方法の更新」
   - 「請求書のダウンロード」（任意）
3. **保存**

> テスト環境では初期状態で無効になっており、「テスト環境のリンクを有効化」を
> 押す必要がある場合があります。

### 2-4. Webhook（イベントの送信先）を作る

Stripe は「開発者ダッシュボード」を **Workbench** に置き換えています。新しい画面での手順です。

1. ダッシュボードの **Workbench** を開き、**Webhooks** タブを選ぶ
   （直リンク: <https://dashboard.stripe.com/webhooks>）
2. **「イベントの送信先を作成」** をクリック
3. イベントの受信元 → **「アカウント」** を選ぶ（連結アカウントではありません）
4. API バージョンはアカウントの既定のままで問題ありません
5. **イベントタイプ**で次の6つを選ぶ
   - `checkout.session.completed`
   - `customer.subscription.created`
   - `customer.subscription.updated`
   - `customer.subscription.deleted`
   - `invoice.payment_failed`
   - `charge.refunded`
6. **続行** → 送信先の種類は **「Webhook エンドポイント」**
7. **続行** → エンドポイント URL に次を入力
   ```
   https://emu-realtime.onrender.com/api/billing/webhook
   ```
8. 作成後、そのエンドポイントを開き、署名シークレットの **「クリックして表示」** から
   **`whsec_` で始まる値をコピーして控える**

> 旧画面（開発者 → Webhook）をまだ使っている場合は、「エンドポイントを追加」から
> 同じ URL とイベントを登録すれば同じ結果になります。

### 2-5. シークレットキーを取得

**開発者 → API キー**（または Workbench の API キー）から
**シークレットキー**をコピーして控える。テストモードなら `sk_test_`、本番モードなら `sk_live_` で始まります。
表示は一度きりのことがあるので、その場で 3 の環境変数に貼ってください。

## 3. Render：環境変数を設定

バックエンド（Render）の Environment に追加します。**Vercel ではありません。**

| 変数 | 値 |
|---|---|
| `STRIPE_SECRET_KEY` | シークレットキー。**テスト中は `sk_test_...`、本番で `sk_live_...`** |
| `STRIPE_PRICE_ID` | 2-2 で控えた価格ID（`price_...`）。**モードごとに別の値** |
| `STRIPE_WEBHOOK_SECRET` | 2-4 で控えた署名シークレット（`whsec_...`）。**モードごとに別の値** |
| `PUBLIC_SITE_ORIGIN` | `https://schoolpark-emu.vercel.app`（省略可・既定値と同じ）|
| `SP_OWNER_ADDRESS` | 管理画面を使えるウォレットアドレス（省略時は既定のオーナーアドレス）|

> **シークレットキーを Git に入れないでください。** フロントエンドにも置かないでください。
> 漏れた場合、第三者が返金や顧客情報の取得を実行できます。

設定後、Render で再デプロイすると `⚠️ STRIPE_SECRET_KEY 未設定` の警告が消えます。

## 5. 公開前に必ずやること

### 5-1. 特商法の記載（記入済み）

`frontend/public/tokushoho.html` に事業者情報を記入済みです。
所在地・電話番号・メールアドレスは**誰でも見られる公開ページに載ります**。
自宅住所や個人の携帯番号を出したくない場合は、バーチャルオフィスや
問い合わせ専用の番号・アドレスに差し替えてください。

郵便番号（〒813-0042）と受付時間（9:00〜17:00）も記入済みです。

### 5-2. 本人確認の考え方

**書類の画像は預かりません。** Emu は金融機関ではないので、犯罪収益移転防止法の
取引時確認の対象ではありません。書類の提出は法律上の義務ではなく、安全のための自主的な措置です。

対話の相手はオーナー本人で、全会員と1対1で話します。**画面越しに顔を見て話す方が、
送られてきた画像より確実に本人を確かめられます**（他人の免許証の画像を送るのは簡単ですが、
その人になりすまして45分話すのは無理です）。

一方で書類の画像は、漏れたときの被害が最も大きい種類の個人情報です。
預かる以上は保管・削除・閲覧制御の責任がずっと付いて回ります。
得られる確実性が対話に劣るのに、リスクだけ大きい。だから預かりません。

いま行っているのは次の4つです。

1. 決済が通ること（実在するカードが必要なので、使い捨てアカウントを量産できない）
2. 入会時に18歳以上であることの確認（チェックしないと入会ボタンが押せない）
3. 最初の対話で、オーナーが画面越しに本人を確認する
4. 管理画面の「本人確認」タブで「確認済みにする」を押す

記録されるのは**確認した事実・日付・方法だけ**です。氏名も生年月日も画像も保存しません。

### 5-3. 対話機会を提供できる状態にする

保証は「30日間で最低4回の対話機会を提供する」ことが前提です。対話の相手は creator（オーナー）本人が
務める前提で設計しています。会員が増えて4回×人数をこなせなくなった時点で、
**保証条件を満たせなくなり全員が返金対象になります**。募集人数は、月に対応できる対話数から逆算してください。

目安: 1人あたり月4回 → 10人で月40回。1回45分なら月30時間。

### 5-4. 動作確認（テストモードで・必須）

`STRIPE_SECRET_KEY` をテストキー（`sk_test_...`）、`STRIPE_PRICE_ID` と `STRIPE_WEBHOOK_SECRET` も
**テストモードで作ったもの**にして、通しで確認します。

テストカード: `4242 4242 4242 4242` / 有効期限は未来の日付 / CVCは任意の3桁 / 郵便番号は任意

| # | 確認すること | 通らないときに疑う場所 |
|---|---|---|
| 1 | `/membership.html` で「入会して支払う」→ Stripe の決済画面へ遷移 | `STRIPE_PRICE_ID` がテストモードの価格か |
| 2 | 決済後 `?billing=success` で戻り、状態が**「有効」**になる | Webhook が届いていない。Workbench のイベント配信タブで 200 が返っているか見る |
| 3 | **次回更新日が表示される** | `current_period_end` の読み取り（SubscriptionItem 側） |
| 4 | 「支払い方法の変更・解約」→ 顧客ポータルが開く | テスト環境のポータルが有効化されているか（2-3） |
| 5 | ポータルで解約 → 状態が「この日で終了」に変わる | `customer.subscription.updated` がイベントに入っているか |
| 6 | 18歳以上のチェックを入れないと入会ボタンが押せない | — |
| 7 | 管理画面で対話機会を提示 → 会員側に出る → 評価できる | — |
| 8 | **返金**：申請 → 管理画面で承認 → Stripe に返金が記録される | ここは 2026-07-29 の API 変更で一度壊れていた箇所。**必ず通すこと** |
| 9 | Firestore の `billing_events` にイベントIDが記録されている | 二重処理の防止が効いている証拠 |

> **8 の返金だけは、申請期間（入会31日目から7日間）を待たないと試せません。**
> テストのために一時的に試すなら、Firestore の `subscriptions/{uid}` の `firstSubscribedAt` を
> 32日前の日付に書き換えてから申請してください（テスト環境のデータでのみ行うこと）。

### 5-5. 本番モードへの切り替え

テストが全部通ってから行います。**商品・価格・ポータル・Webhook をすべて本番モードで作り直します**
（2-2 〜 2-4 をもう一度）。そのうえで Render の3つの環境変数を本番の値に差し替え、
自分のカードで1回だけ実際に決済して、すぐ返金して確認するのが確実です。

## 6. 運用

### 管理画面
`https://schoolpark-emu.vercel.app/membership-admin.html`

**このURLは外部に出さないでください。** `noindex` は入れていますが、URLを知られると
アクセス自体は試みられます（オーナー以外は 403 になります）。

4つのタブがあります。

- **返金申請** — 申請一覧。「対話記録を見る」で条件を満たすか自動判定した結果を確認してから承認する。
  **承認すると即座に Stripe から返金され、取り消せません。**
- **本人確認** — 書類は預かりません。最初の対話で確認できたら「確認済みにする」を押すだけ。
- **対話記録** — 対話機会の提示と、実施結果の記録。ここの記録が返金判定の根拠になる。

### 返金の判定

管理画面の「対話記録を見る」が次を表示します。

| 項目 | 意味 |
|---|---|
| 提示した機会 | Emu が提示した対話の総数 |
| 実施 | 実際に行われた回数 |
| また話したい | 会員が「また話したい」と評価した数 |
| Emu側都合の不成立 | 中止・相手を用意できなかった回数 |
| 本人都合の欠席 | 無断欠席・本人キャンセル |
| 返金条件を満たすか | 3回以上参加・全て評価済み・「また話したい」が0 のとき「満たす」 |

「満たさない」でも承認は可能です（最終判断はオーナー）。ただし規約に書いた条件と
異なる運用を続けると、規約自体が意味を失うので注意してください。

### 監査ログ
`admin_audit_logs` に、本人確認書類の閲覧・返金の承認/却下・対話記録の操作が残ります。
クライアントからは読み書きできません。

## 7. 対話の進め方（2026-08-15 追加）

対話の相手はオーナー本人。場は2種類あり、会員が希望を出せる。

- **Emu内で対話** … 議論ルーム(room3)でそのまま話す。追加の準備は要らない
- **Zoom** … 会員が希望したら、管理画面でURLを入れて提示する

**流れ**
1. 会員がプロフィールと興味・関心テーマ、対話できる日時を登録する
2. 管理画面「対話記録」→「対話機会を提示する」で uid・日時・場を入れる
   （Zoomを選んだときだけURL欄が必要）
3. 会員側の画面に「Emuで対話する」または「Zoomに参加する」が出る
4. 対話後、管理画面で結果（実施済み／欠席／中止など）を記録する
5. **双方が「また話したい」を回答する**。会員は自分の画面、オーナーは管理画面から

5 を両方入れないと相互マッチ率が出ない。ここが最重要指標なので、対話ごとに必ず入れる。

## 8. 指標の見方

管理画面の「指標」タブ。ブリーフ §24 に対応する。

| 指標 | 意味 |
|---|---|
| **相互マッチ率** | 双方が「また話したい」と答えた割合。**最重要**。成約率より先に見る |
| 継続相手が一人以上いる会員の割合 | 相互マッチが1件でもある会員の比率 |
| 内訳 | 実施数／会員側の「また話したい」／あなた側の「また話したい」 |

片方だけの「また話したい」は相互マッチに数えない。
両方そろった対話が0件のうちは、相互マッチ率は「—」と出る。

## 10. 参考：ログインメールを自前で送る場合の費用

Firebase 標準のログインメール（`Sign in to %APP_NAME%`）は無料で、文面は編集できません。
自分の言葉（例「SchoolPark のログインに必要です」）で送りたい場合は、バックエンドで
ログインリンクを生成し、自前でメールを送ることになります。

| 項目 | 費用 |
|---|---|
| リンク生成（Firebase Admin SDK の `generateSignInWithEmailLink`） | **無料**（Auth の機能） |
| Render のバックエンド | **追加費用なし**（既存を使う） |
| メール配信サービス | **無料枠で足りる**（下記） |
| **独自ドメイン** | **年 1,000〜2,000円程度。ここだけ実費** |

**メール配信サービスの無料枠（2026年8月時点）**
- **Resend** … 月3,000通 / 日100通、独自ドメイン1つ。トランザクションメール向けで最有力
- **Brevo** … 日300通
