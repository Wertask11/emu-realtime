## 1. Firebase：メールログインを有効化

Firebase コンソール（<https://console.firebase.google.com/> → プロジェクト `emusch-2a111`）:

1. 左メニューの **構築 → Authentication** を開く
2. 上部の **Sign-in method** タブを開く
3. プロバイダ一覧から **「メール / パスワード」** を選ぶ
   （すでに有効な場合は、行の右端の鉛筆アイコンから編集画面へ）
4. 編集画面に **トグルが2つ**あります。**両方をオンにする**
   - 「メール / パスワード」… 有効にする
   - **「メールリンク（パスワードなしでログイン）」… 有効にする** ← これが本命
5. **保存** をクリック

> パスワード認証は使いませんが、Firebase の仕様上、メールリンクはこのプロバイダの
> 配下にあるため、親のトグルもオンにする必要があります。

6. **Authentication → Settings → 承認済みドメイン** に `schoolpark-emu.vercel.app` が
   入っていることを確認する（無ければ「ドメインを追加」）

> **間違えやすい点**: 「テンプレート」タブ（URL が `/authentication/emails`）はメール本文の
> 編集画面で、ここでは有効化できません。**Sign-in method** タブ（`/authentication/providers`）です。

7. **テンプレート**タブ → 左下の **テンプレート言語** を **日本語** にする
   （既定は英語で、ログイン用メールが英語のまま届きます）

送信元は初期状態で `noreply@emusch-2a111.firebaseapp.com` です。これで動きますが、
迷惑メールに振り分けられやすいので、「届かない」という声が出たら
テンプレートタブの **SMTP 設定** から独自ドメインの送信サーバーに切り替えてください。

**確認方法**: 本番サイトのログイン画面で「メールではじめる」→ 自分のアドレスを入れて送信。
「ログイン用のリンクを◯◯に送りました」と出て、実際にメールが届けば成功です。

| 出たエラー | 原因 |
|---|---|
| メールログインが Firebase で未有効です | 手順4のトグルが入っていない（`auth/operation-not-allowed`）|
| このドメインが承認済みドメインに未登録です | 手順6が未実施（`auth/unauthorized-continue-uri`）|

> 届いたメールのリンクを開くと `?oobCode=...` 付きで戻ってきて、自動でログインします。
> 別の端末でリンクを開いた場合は、確認のためメールアドレスの再入力を求めます。

## 2. Stripe：アカウントと商品の作成（**オーナー自身の作業**）

私（Claude）は金融情報の入力とアカウント開設ができません。ここはご自身で行ってください。

### 2-1. アカウント作成と本番有効化

1. <https://dashboard.stripe.com/register> でアカウントを作成
2. 事業者情報・銀行口座を登録し、**本番の有効化（Activate）を完了**する
   - 合同会社型DAO SchoolPark として登録
   - 代表者の本人確認書類の提出が必要です
   - 審査に数営業日かかることがあります

### 2-2. 商品と価格を作る

1. ダッシュボード上部の **カタログ（Product catalog）** を開く
2. 右上の **「商品を追加」**
3. 入力する
   - 商品名: `Emu 有料会員`
   - 料金体系: **定期的（Recurring）** ← ここを「一括」にしないこと
   - 金額: **10000**、通貨: **JPY**
   - 請求期間: **月次**
4. 保存すると価格が作られます。価格の詳細を開き、
   **価格ID（`price_` で始まる文字列）をコピーして控える**

### 2-3. カスタマーポータルを有効化（解約導線）

1. **設定（歯車アイコン）→ Billing → カスタマーポータル**
2. 機能の中で次をオンにする
   - **「サブスクリプションのキャンセル」** ← これが会員の解約導線になります
   - 「支払い方法の更新」
   - 「請求書のダウンロード」（任意）
3. **保存**

> テスト環境では初期状態で無効になっており、「テスト環境のリンクを有効化」を
> 押す必要がある場合があります。

### 2-4. Webhook（イベントの送信先）を作る

Stripe は「開発者ダッシュボード」を **Workbench** に置き換えています。新しい画面での手順です。

1. ダッシュボードの **Workbench** を開き、**Webhooks** タブを選ぶ
   （直リンク: <https://dashboard.stripe.com/webhooks>）
2. **「イベントの送信先を作成」** をクリック
3. イベントの受信元 → **「アカウント」** を選ぶ（連結アカウントではありません）
4. API バージョンはアカウントの既定のままで問題ありません
5. **イベントタイプ**で次の6つを選ぶ
   - `checkout.session.completed`
   - `customer.subscription.created`
   - `customer.subscription.updated`
   - `customer.subscription.deleted`
   - `invoice.payment_failed`
   - `charge.refunded`
6. **続行** → 送信先の種類は **「Webhook エンドポイント」**
7. **続行** → エンドポイント URL に次を入力
   ```
   https://emu-realtime.onrender.com/api/billing/webhook
   ```
8. 作成後、そのエンドポイントを開き、署名シークレットの **「クリックして表示」** から
   **`whsec_` で始まる値をコピーして控える**

> 旧画面（開発者 → Webhook）をまだ使っている場合は、「エンドポイントを追加」から
> 同じ URL とイベントを登録すれば同じ結果になります。

### 2-5. シークレットキーを取得

**開発者 → API キー**（または Workbench の API キー）から
**シークレットキー（`sk_live_` で始まる）** をコピーして控える。
表示は一度きりのことがあるので、その場で 3 の環境変数に貼ってください。

## 3. Render：環境変数を設定

バックエンド（Render）の Environment に追加します。**Vercel ではありません。**

| 変数 | 値 |
|---|---|
| `STRIPE_SECRET_KEY` | Stripe のシークレットキー（`sk_live_...`）|
| `STRIPE_PRICE_ID` | 2-3 で控えた価格ID（`price_...`）|
| `STRIPE_WEBHOOK_SECRET` | 2-5 で控えた署名シークレット（`whsec_...`）|
| `PUBLIC_SITE_ORIGIN` | `https://schoolpark-emu.vercel.app`（省略可・既定値と同じ）|
| `SP_OWNER_ADDRESS` | 管理画面を使えるウォレットアドレス（省略時は既定のオーナーアドレス）|

> **シークレットキーを Git に入れないでください。** フロントエンドにも置かないでください。
> 漏れた場合、第三者が返金や顧客情報の取得を実行できます。

設定後、Render で再デプロイすると `⚠️ STRIPE_SECRET_KEY 未設定` の警告が消えます。

## 5. 公開前に必ずやること

### 5-1. 特商法の記載（記入済み）

`frontend/public/tokushoho.html` に事業者情報を記入済みです。
所在地・電話番号・メールアドレスは**誰でも見られる公開ページに載ります**。
自宅住所や個人の携帯番号を出したくない場合は、バーチャルオフィスや
問い合わせ専用の番号・アドレスに差し替えてください。

郵便番号と電話の受付時間は未記入です（いただいていないため空欄のままにしています）。
記載したい場合は同ファイルの該当行に追記してください。

### 5-2. 対話機会を提供できる状態にする

保証は「30日間で最低4回の対話機会を提供する」ことが前提です。対話の相手は creator（オーナー）本人が
務める前提で設計しています。会員が増えて4回×人数をこなせなくなった時点で、
**保証条件を満たせなくなり全員が返金対象になります**。募集人数は、月に対応できる対話数から逆算してください。

目安: 1人あたり月4回 → 10人で月40回。1回45分なら月30時間。

### 5-3. 動作確認（テストモードで）

Stripe をテストモードに切り替え、`STRIPE_SECRET_KEY` をテストキー（`sk_test_...`）にして通しで確認します。
テストカード番号: `4242 4242 4242 4242`（有効期限は未来の日付、CVCは任意の3桁）

確認する項目:
1. `/membership.html` で「入会して支払う」→ Stripe の決済画面へ遷移する
2. 決済後 `?billing=success` で戻り、状態が「有効」になる（Webhook が届いている証拠）
3. 「支払い方法の変更・解約」→ Stripe の顧客ポータルが開く
4. 本人確認を提出 → `/membership-admin.html` に表示される → 表示・承認できる → **画像が消える**
5. 管理画面で対話機会を提示 → 会員側に表示される → 評価できる
6. Firestore の `billing_events` にイベントIDが記録されている（二重処理の防止が効いている）

## 6. 運用

### 管理画面
`https://schoolpark-emu.vercel.app/membership-admin.html`

**このURLは外部に出さないでください。** `noindex` は入れていますが、URLを知られると
アクセス自体は試みられます（オーナー以外は 403 になります）。

3つのタブがあります。

- **返金申請** — 申請一覧。「対話記録を見る」で条件を満たすか自動判定した結果を確認してから承認する。
  **承認すると即座に Stripe から返金され、取り消せません。**
- **本人確認** — 「書類を表示」で5分間だけ画像を見られる。承認または却下すると画像は即削除。
- **対話記録** — 対話機会の提示と、実施結果の記録。ここの記録が返金判定の根拠になる。

### 返金の判定

管理画面の「対話記録を見る」が次を表示します。

| 項目 | 意味 |
|---|---|
| 提示した機会 | Emu が提示した対話の総数 |
| 実施 | 実際に行われた回数 |
| また話したい | 会員が「また話したい」と評価した数 |
| Emu側都合の不成立 | 中止・相手を用意できなかった回数 |
| 本人都合の欠席 | 無断欠席・本人キャンセル |
| 返金条件を満たすか | 3回以上参加・全て評価済み・「また話したい」が0 のとき「満たす」 |

「満たさない」でも承認は可能です（最終判断はオーナー）。ただし規約に書いた条件と
異なる運用を続けると、規約自体が意味を失うので注意してください。

### 監査ログ
`admin_audit_logs` に、本人確認書類の閲覧・返金の承認/却下・対話記録の操作が残ります。
クライアントからは読み書きできません。
